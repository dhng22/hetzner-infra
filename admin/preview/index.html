Call it from your pipeline
curl -fsS -X POST https://admin-aichat.acme.dev/hooks/deploy/api \ -H 'X-Deploy-Token: preview-token-not-real-000000' \ -H 'Content-Type: application/json' \ -d '{"image": "ghcr.io/you/app:sha-'"$GITHUB_SHA"'"}'
One token per component, so a leaked staging token cannot reach production. The update is graceful because of the service's own policy, not this endpoint: start-first brings the new task to healthy before stopping the old one, monitor gives it time to boot before Swarm judges it, and a failure rolls back automatically. The call waits for that and returns 502 if Swarm rolled the deploy back, so a bad image fails your pipeline instead of quietly reverting. :latest is rejected — Swarm compares the reference string, so an unchanged tag is a silent no-op. If the panel is behind Cloudflare Access, exempt this path or give CI a service token.

Autoscaler

Load is absorbed cheapest first: replicas in seconds, nodes in about two minutes. Coming down the order reverses — shed replicas first, remove the node later. The master is not a worker: it is the control plane, and while no worker exists it carries your components itself and nothing is billed. Capacity is measured from real CPU and memory, never configured, and each component's scaling policy travels with it as labels on its own service.
