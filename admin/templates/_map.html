The same tree as the Overview map, deliberately: it is the same fleet and the same blocks, so the two read as one picture. What changes is what a block MEANS. On the Overview a block is "some task", named after its service; here every block is a replica of this component and named after its tag, because when every block says the same thing the only interesting question is which ones do not. That makes a rolling update something you look at rather than compute: two colours while it rolls, one when it is done, and two that stay two when it is stuck — which is the state the Deployments tab can only tell you about after the fact. #}
