When nothing is happening, this is the answer to why. Every gate a topology change has to pass increments its own counter, so a database that is not growing names the reason rather than leaving you to read a log — cooldown is waiting out the hours since the last change, no_backup is a backup target that has never produced one, backup_stale is one that has stopped, no_majority is a set that has lost members, member_syncing is a copy in progress, and another_sync_in_flight is another database being copied right now — only one may run at a time, because a sync reads the whole dataset off a live member.
